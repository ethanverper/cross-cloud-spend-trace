# 0001. Select and reshape "Credit Watch" into spend-lens as Cowork OS's first technology project

Date: 2026-08-12
Status: accepted

## Context

`trend-scout` produced a data-engineering research brief (`docs/research/technology/2026-08-12-data-engineering-landscape.md`), and `innovation-strategist` turned it into a 5-idea shortlist (`docs/ideation/technology/2026-08-12-data-engineering-shortlist.md`): Stack Pulse, Pipeline Pilot, Credit Watch, Metric Bridge, Skip Spark. The shortlist's own recommendation named **Stack Pulse** as the top pick and **Credit Watch** as effectively "Stack Pulse's v1 (cost half) built standalone and safer." This is Cowork OS's first project in the `technology` domain and the first technology-category pick under the weekly cadence policy (`docs/decisions/0001-weekly-project-cadence.md` at the root) for the week of 2026-08-10 → 2026-08-17.

Ethan picked **Credit Watch** over the shortlist's top recommendation, then substantially reshaped it through direct conversation before scaffolding — the resulting project, **spend-lens**, is materially different from the shortlist's own "Credit Watch" entry in scope and stack, not a straight pickup.

## Decision

Selected and reshaped Credit Watch into **spend-lens** — a multi-platform cost-attribution and forecasting tool for data infrastructure spend, giving real-time visibility into which query, job, or pipeline is costing money, with a forecast, before the bill surprises anyone.

**What changed from the shortlist's "Credit Watch" entry, and why:**

1. **Source scope: Snowflake/BigQuery → AWS + Snowflake + Databricks.** The shortlist entry scoped to Snowflake (with BigQuery as a v2). Ethan explicitly redirected toward AWS, Snowflake, and Databricks for v1 instead — per `docs/about-me.md` point 3 (his explicit 2026-08-12 ask that technology-domain projects weight toward tools that actually appear in big-tech data engineering job postings, not just what's trendy in small-team/indie-hacker discourse). AWS extends his existing S3/Lambda/Redshift experience into real cost-attribution work; Snowflake deepens an existing but shallow "Snowflake-based ETL workflows" line from PSL Group; Databricks is genuinely new territory with high resume value. BigQuery/GCP was dropped from consideration entirely (not even a v2 note) in favor of this AWS-first framing, and Azure was added as a named future direction alongside GCP — both **explicit v2/v3 scope, not built now**. This was a deliberate scope-discipline call Ethan made directly ("no me quiero comer el mundo en un proyecto") — three sources for v1, full stop, not a soft target.
2. **Added PySpark on Databricks as the aggregation layer.** Not present in the original Credit Watch concept at all. Real reinforcement of Ethan's Tesla PySpark/Airflow experience (20M+ daily manufacturing/warranty records via Airflow/PySpark ETL) — processing/aggregating the raw usage/billing logs at volume, not an artificial exercise bolted on for keyword coverage.
3. **Added Docker containerization per source collector.** Also not in the original concept. One collector service per source (AWS/Snowflake/Databricks), containerized for realistic, reproducible deployment — genuinely new for Ethan, and a concrete, demonstrable answer to "can you deploy real infrastructure," not just "can you query an API."
4. **Renamed Credit Watch → spend-lens.** Per the team's naming standard (public GitHub repo name, evocative of the actual mechanism, no throat-clearing filler suffix) — "Credit Watch" reads as generic financial-services naming and doesn't communicate the actual mechanism (a lens onto infrastructure spend) the way `factor-lens` does for its own domain.
5. **Ownership reassignment: `business-intelligence` owns the dashboard, KPI design, and forecast visualization outright — not `quant-analyst`.** The shortlist entry's own feasibility read already named `business-intelligence` for the dashboard; this decision makes explicit that there is no statistical/financial model here to justify `quant-analyst` involvement at all — this is cost aggregation and reporting, a `business-intelligence` mandate end to end, including the rule-9a Interpretation & Key Takeaways content (framed as "what this spend pattern implies," never prescriptive advice).

**A load-bearing, explicit dependency this decision creates**: Ethan does not currently have active AWS, Snowflake, or Databricks accounts. Rather than design against synthetic/faked usage data, Ethan explicitly chose (when asked directly) to start from scratch — create free-tier/trial accounts on all three platforms and generate minimal real activity so spend-lens has genuine, if small-scale, data to measure. Per standing team policy, no agent may create these accounts, enter payment details, or complete any signup/OAuth flow on Ethan's behalf. This is written into the roadmap as a **blocking Phase 1**, human-only, with a concrete step-by-step checklist — no build work on the actual data-integration code starts until it's done.

## Consequences

- Scaffolded at `projects/technology/spend-lens/` with a v1 roadmap phased: Phase 1 (human prerequisite — account creation/activity generation) → Foundation & Data Integration (`developer`) → Cost Attribution/Aggregation/Forecast Core incl. PySpark on Databricks (`developer`) → Brand & Identity Direction (`brand-creative`) → Dashboard/KPI/Forecast Visualization (`business-intelligence`) → Learning & Glossary (`educator`) → Multi-Cloud Credential Security Review (`cyber-security`) → QA Sign-off (`qa-tester`) → Publish (`developer`) → Deploy (`devops`).
- `docs/project-standards.md`'s full section/interactivity/content-decomposition requirements (rules 1, 2, 4-9a, 14, 15, 16) are scoped into the phase plan explicitly from the start, with named ownership per rule 15's actual ownership line — a deliberate attempt to avoid Factor Lens's own history of needing a sixth round of feedback before content decomposition was treated as a day-one planning step rather than a late retrofit.
- `docs/ideation/index.md` updated: technology row marked `selected → projects/technology/spend-lens/`.
- `docs/ideation/technology/2026-08-12-data-engineering-shortlist.md` gets an outcome note (not a rewrite) recording that Credit Watch was picked and reshaped into spend-lens.
- `docs/portfolio.md` and `docs/cadence.md` updated to reflect the week's first technology-category project.
- Stack Pulse, Pipeline Pilot, Metric Bridge, and Skip Spark remain unselected in `docs/ideation/index.md` for future consideration — not rejected, just not picked this round. Per the shortlist's own overlap note, if Stack Pulse is ever picked later, its cost-focused v1 pillar substantially overlaps with what spend-lens now covers — worth reconciling explicitly at that point rather than building a duplicate.
